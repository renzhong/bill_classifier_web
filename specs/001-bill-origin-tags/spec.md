# Feature Specification: 账单归属标签

**Feature ID**: `001-bill-origin-tags`
**Created**: 2026-09-24
**Status**: Implemented
**Input**: 用户上传多份账单后，希望逐笔看出来源；上传标签应保留在每笔账单上，并可在明细中修改。

## User Scenarios & Testing

### User Story 1 - 上传后保留标签 (Priority: P1)

用户上传不同成员或来源的账单并选择标签后，汇总明细中的每笔新账单都显示上传时选择的标签。

**Why this priority**: 汇总账单需要保留归属，方便核对个人花销。

**Independent Test**: 为两份合成账单分别选不同标签上传，逐笔查看并按标签过滤。

**Acceptance Scenarios**:

1. **Given** 用户有两个标签，**When** 分别上传两份账单并选择对应标签，**Then** 每笔新账单保留各自标签。
2. **Given** 上传时选择多个标签，**When** 上传完成，**Then** 每笔新账单保留全部所选标签。
3. **Given** 同一账单再次上传，**When** 重复行被跳过，**Then** 原账单及其已修改的标签保持不变。

### User Story 2 - 在明细中查看与编辑 (Priority: P2)

用户能看到每笔账单的来源、归属人和标签，并能增删自己拥有的标签。

**Why this priority**: 上传时可能选错，逐笔修正应方便可靠。

**Independent Test**: 修改一笔账单的标签，刷新并再次按标签筛选。

**Acceptance Scenarios**:

1. **Given** 一笔已有标签的账单，**When** 用户修改并保存，**Then** 刷新后仍显示新标签。
2. **Given** 另一个用户的标签，**When** 尝试将其加到账单，**Then** 修改被拒绝。

### Edge Cases

- 无有效账单或部分行失败时，只有成功入库的新账单继承标签。
- 历史上传任务已保存标签但账单缺关联时，应补上有效标签，不删除已有账单标签。
- 删除标签后，账单不再显示它。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须把上传时所选标签关联到该次新入库的每笔账单。
- **FR-002**: 明细页必须逐笔显示来源、归属人和标签。
- **FR-003**: 用户必须能逐笔增删自己拥有的标签，修改后持久保留。
- **FR-004**: 按标签过滤必须依据账单当前标签。
- **FR-005**: 重复上传不能覆盖已有账单的标签。
- **FR-006**: 历史上传任务中已保存的有效标签必须补齐到账单，保留已有标签。
- **FR-007**: 用户不能将别人的标签关联到自己的账单。

### Key Entities

- **上传任务**：一次上传所选择的标签、来源及可选归属人。
- **账单**：逐笔收支，具有来源、可选归属人及零个或多个标签。
- **标签**：用户自定义的归属或用途标记。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 两份带不同标签的合成账单上传后，100% 的新账单显示正确标签。
- **SC-002**: 标签逐笔增删后，刷新页面仍 100% 保持修改。
- **SC-003**: 按标签筛选出的账单 100% 具有该标签。
- **SC-004**: 历史任务的有效标签可在对应账单看到，且已有人工标签不丢失。

## Assumptions

- 保留现有平台来源和 `owner` 文本；标签是可编辑的补充标记。
- 一笔账单允许多个标签，可以同时表达所属人和用途。
- 重复上传保持幂等，不借重复文件修改已有账单标签。
