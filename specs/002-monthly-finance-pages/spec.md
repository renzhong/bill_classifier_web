# Feature Specification: 五类财务页面与月度口径

**Feature Branch**: codex/next-prd
**Created**: 2026-09-24
**Status**: Implemented
**Input**: 用户指定五类页面，账单页延续旧版表格与行内分类操作；上传后先解析预览，用户再触发规则分类和归档。资产项跨月复用，投资估值自动计入月度资产。

## User Scenarios & Testing *(mandatory)*

五项均为本轮产品目标。以下 P1 表示同级需求，不代表用户已指定开发顺序。

### User Story 1 - 账单解析、分类与归档 (Priority: P1)

用户点击上传按钮，在弹窗内选择一份账单文件、支付宝或微信格式及可选的多个标签，不选月份。系统按每笔交易时间解析并展示在临时表格；用户点击按钮运行一条默认的名称正则测试规则，在临时表格中直接用“类别”下拉框修正结果，最后归档。归档账单仍用相同列按月查询，类别平时只展示，点击后才出现下拉框。本轮不设计规则管理页。

**Why this priority**: 账单数据是分类汇总的基础。
**Independent Test**: 在弹窗内选文件、平台和可选的多个标签，上传含跨月交易的合成账单，核对临时表格；点击开始分类，验证名称包含“地铁”的账单被测试规则归入“交通”，行内改类后归档；验证跨月查询、人工类别和来源只读。

**Acceptance Scenarios**:

1. **Given** 用户点击“上传账单”，**When** 弹窗打开，**Then** 可选择文件、支付宝或微信格式及可选的多个标签，并看到支持 CSV/XLSX 的说明，无需选择月份。
2. **Given** 用户上传一份跨月账单，**When** 解析完成，**Then** 在无首列复选框的临时表格查看每笔交易的时间、名称、商户、收/支、来源、金额、类别与分类规则，且尚未自动执行分类；平台和标签均只读。
3. **Given** 临时账单已解析，**When** 用户点击“开始分类”，**Then** 只运行默认的名称正则测试规则“地铁|公交 → 交通”，表格显示类别与命中规则；本轮没有规则编辑或规则管理页。
4. **Given** 临时账单有自动分类结果，**When** 用户在始终可见的类别下拉框中修改结果，**Then** 修改立即可见，后续规则或 AI 不覆盖人工结果，也无需逐笔点击 Review。
5. **Given** 临时账单已完成修正，**When** 用户归档，**Then** 每笔账单按交易时间归入相应月份，月度表格保持与临时表格相同的列；类别默认只展示结果，点击后可下拉修改，来源仍只读。
6. **Given** 用户查询归档账单，**When** 使用月份、平台、标签、类别及名称/商户关键词筛选，**Then** 可以查看结果并分页，表格不出现批量选择框。

### User Story 2 - 每月账单分类汇总 (Priority: P1)

用户选择月份，查看每个分类的花费金额，并进入该分类对应的账单明细。

**Why this priority**: 用户要知道每月的钱具体花在哪里。
**Independent Test**: 给定多类、多月的合成账单，选择一个月后核对各类金额与该月明细之和。

**Acceptance Scenarios**:

1. **Given** 某月有多类支出，**When** 打开该月分类汇总，**Then** 显示每类支出及该月支出合计。
2. **Given** 用户选择某个分类，**When** 点击查看明细，**Then** 明细仅显示所选月份及分类的账单。
3. **Given** 某月没有支出，**When** 查看该月，**Then** 显示空状态和零支出，不引用其他月份数据。

### User Story 3 - 每月资产汇总与录入 (Priority: P1)

用户先创建可命名的资产项和负债项，例如“招商银行储蓄卡”“微信余额”“支付宝余额”。以后切换月份时，页面沿用项目清单，用户只填写或修改每项当月金额；同页显示资产总额、负债总额和净资产。投资项当月估值自动进入本月资产汇总。

**Why this priority**: 用户需要按月维护完整的资产和负债，并直接看到总额。
**Independent Test**: 创建两个资产项和一个负债项，分别填写连续两个月的金额；核对新月份无需重建项目、金额未被自动沿用，并验证投资估值只计入一次。

**Acceptance Scenarios**:

1. **Given** 用户已创建多个命名资产项和负债项，**When** 切换到新月份，**Then** 同一批未停用项目自动列出，金额显示为待填写，无需逐项重建。
2. **Given** 用户为某月填写各项金额，**When** 保存，**Then** 同页显示各项金额、资产总额、负债总额和净资产。
3. **Given** 投资项已有当月估值，**When** 查看当月资产汇总，**Then** 估值自动出现、只计入一次，并标明来自投资页。
4. **Given** 某资产项当月尚未填写，**When** 查看资产汇总，**Then** 该项标记待填写，当月合计标明数据未齐，且不把空值当成零。
5. **Given** 用户停用某资产项，**When** 切换至后续月份，**Then** 该项不再要求填写，但历史月份金额仍可查看。
6. **Given** 旧版已有按月录入的资产，**When** 升级后打开对应月份，**Then** 历史金额仍可查看，并能继续在新月份使用关联的资产项。

### User Story 4 - 管理投资项与月度盈亏 (Priority: P1)

用户新增投资项，记录本金和每月买入、卖出，录入当月现值，查看每项当月盈亏与总投资情况。

**Why this priority**: 用户需要把投资的资金流和价值变化与一般账户余额分开查看。
**Independent Test**: 新增投资项，在连续两月录入本金、买卖及现值，核对当月盈亏及资产页自动计入的估值。

**Acceptance Scenarios**:

1. **Given** 用户创建投资项并填写本金，**When** 记录某月买入或卖出，**Then** 可按月查看资金变化和当月现值。
2. **Given** 某月及上月已有估值，**When** 查看当月盈亏，**Then** 按“本月末估值 − 上月末估值 − 本月买入额 + 本月卖出额”自动计算并展示口径。
3. **Given** 投资项在首月有初始本金和月末估值，**When** 查看首月盈亏，**Then** 以上述公式中的“上月末估值”为初始本金计算。
4. **Given** 某月未录入估值，**When** 查看该月，**Then** 不显示伪造的盈亏或估值，并提示补录。
5. **Given** 非首月缺少上月末估值，**When** 查看当月盈亏，**Then** 提示补录上月估值，不把缺失值当作零。

---

### User Story 5 - 逐笔收入与月年汇总 (Priority: P1)

用户按实际发生时间逐笔记录收入金额，可选填来源和备注，并查看月收入、年收入及明细。

**Why this priority**: 同月同来源可能有多笔收入，月度合并记录无法反映实际明细。
**Independent Test**: 同月同来源录入两笔收入，再录入跨月的一笔，核对月收入、年收入及明细。

**Acceptance Scenarios**:

1. **Given** 用户录入一笔收入的时间与金额，**When** 保存，**Then** 明细中显示该笔记录。
2. **Given** 同月同来源已有收入，**When** 再录入一笔，**Then** 两笔均保留且月收入包含两笔。
3. **Given** 用户查看某年，**When** 切换月份或年度，**Then** 对应月收入及年收入等于范围内各笔收入之和。
4. **Given** 旧版仅有按月录入的收入，**When** 升级后查看，**Then** 原金额仍可查询并计入相应月、年合计；未知的具体日期不被伪装为实际发生时间。

### Edge Cases

- 多份账单有重复交易时，分类汇总只计算去重后实际保留的账单；上传时选择的来源标签仍可辨认，且不能逐笔修改。
- 上传时不选择月份；跨月交易归档后分别进入交易时间所属月份。
- 临时账单解析失败行可见，成功行仍可继续分类；未点击开始分类时不自动运行规则。
- 被排除统计的账单不进入月度分类花费；未分类账单单列为“未分类”。
- 负债以非负数录入，资产总额减负债总额得到净资产；资产与账单收入、逐笔收入互不混加。
- 新月仅复用项目定义，不自动沿用上月金额；未填写金额与明确录入的 0 元要能区分。
- 投资项没有该月估值时，页面提示数据不完整，该项不进入该月资产总额；不能用零元误表示真实现值。
- 投资项的上月估值缺失时，不能计算本月盈亏，即使本月估值已录入。
- 同一投资项不能同时作为投资估值和手工资产项目计入一个月的总额。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须通过弹窗提供账单上传：选择文件、支付宝或微信格式及可选的多个标签，说明支持的 CSV/XLSX 格式，不选月份；随后提供解析临时表格、手动触发分类及归档流程。
- **FR-002**: 系统必须在临时与归档账单表格中提供相同列；临时表格的“类别”始终是可操作的下拉框，归档表格先只展示类别，点击该格才进入下拉编辑，完成或取消后恢复展示。来源平台与上传标签均只读，后续自动分类不得将人工改类账单交给 AI 处理或覆盖人工类别。
- **FR-003**: 系统必须按所选月份和分类汇总支出，并能进入同条件的明细。
- **FR-004**: 系统必须在一个每月资产汇总页同时支持资产项与负债项管理、当月金额录入和汇总，不另设独立资产汇总页。
- **FR-005**: 系统必须允许创建和命名可复用的资产项与负债项；新月份自动列出未停用项目，金额默认待填写，并分别显示资产总额、负债总额与净资产。
- **FR-006**: 系统必须将有当月估值的投资项自动计入该月资产汇总，每项只计入一次，并标明来源。
- **FR-007**: 系统必须允许新增投资项，记录本金、逐月买卖金额与当月现值。
- **FR-008**: 系统必须按“本月末估值 − 上月末估值 − 本月买入额 + 本月卖出额”显示投资项当月盈亏；首月以初始本金替代上月末估值，无估值时显示缺失状态。
- **FR-009**: 系统必须允许按实际时间逐笔录入、编辑和删除收入；同月同来源允许多笔。
- **FR-010**: 系统必须由逐笔收入生成月收入与年收入总额，并保留旧版月度收入的可见性与总额。
- **FR-011**: 用户级账单、资产、投资与收入只对所属用户可见和可修改。
- **FR-012**: 系统必须允许在账单页管理分类项；本轮只用一条默认的名称正则规则“地铁|公交 → 交通”测试手动分类流程，不提供规则编辑或规则管理页。
- **FR-013**: 系统必须允许停用资产项或负债项而不丢失历史金额；旧版月度资产记录迁移后仍能按原月份查看。
- **FR-014**: 账单页必须提供月份、平台、标签、类别及名称/商户关键词筛选和分页；临时与归档表格均不设置首列复选框、批量选择操作或逐笔 Review 状态。

### Key Entities *(include if feature involves data)*

- **账单**：交易时间、名称、商户、收/支方向、金额、只读的平台与上传标签、业务类别、命中规则与人工改类标记。
- **临时账单批次**：上传后解析的交易集合，记录解析结果、分类进度及归档进度。
- **测试规则**：本轮仅有一条默认名称正则“地铁|公交 → 交通”，用于验证分类触发与行内修正。
- **资产项与负债项**：持续存在的命名项目，有性质与启用状态；停用不删除历史。
- **项目月度金额**：某项目在某月的金额和可选备注；未填写与明确填 0 元不同。
- **投资估值**：按投资项和月份关联的只读资产来源。
- **投资项**：名称、初始本金、逐月买入和卖出记录、逐月现值。
- **收入记录**：实际发生时间、金额、可选来源与备注；旧月度记录保留原有月份信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 通过弹窗上传跨月合成账单后，100% 成功解析的交易可先在无复选框的临时表格看到，类别可直接下拉；点击开始分类前没有自动分类，之后名称命中测试正则的账单归入交通，归档后每笔进入正确月份，任意一笔点击类别后可下拉修改，来源不可改。
- **SC-002**: 对任意选定月份，分类花费之和与同口径账单明细金额一致，误差不超过 0.01 元。
- **SC-003**: 创建资产项与负债项后，进入下一月份时 100% 未停用项目已列出且金额待填写，无需重新创建；每个有估值的投资项在资产总额中恰好出现一次。
- **SC-004**: 对连续两个月且估值齐全的投资记录，100% 可查看买卖、现值和按统一口径得出的当月盈亏；缺值不会呈现为 0 元盈亏。
- **SC-005**: 同月同来源的至少两笔收入可分别录入；所选月和年的合计与对应逐笔金额之和一致，误差不超过 0.01 元。

## Assumptions

- 本轮定义产品页面与验收口径；分类项在账单页可直接维护，规则管理页及规则编辑另行规划，AI 凭据等低频设置仍可保留辅助入口。
- 表格用“收/支”表示交易方向，用可下拉的“类别”表示用户自定义业务归类；“分类规则”单独显示命中来源。
- 用户点击“归档账单”后，临时批次进入按月查询；分类修正与归档是两个独立操作。
- 投资估值只在明确录入的月份进入资产汇总；缺值不沿用旧值。
- 资产项和负债项每月金额也不默认沿用；可提供手动复制上月金额的快捷操作，但必须由用户主动触发。
- 收入的“时间”至少包含日期，录入和明细可进一步支持时分；月、年按该日期所属自然月和自然年计算。
- 已有月度收入缺少实际日期，应保留为“旧月度记录”，让用户区分其与新逐笔收入。
- 本轮不新增券商或银行的自动同步、投资行情抓取、账单导出能力。
