# 当前分类流程

本文记录已实现的行为。产品规划见 `prd/`，不代表代码现状。

## 用户配置了什么

1. **类别**：模型只能返回当前用户已有的类别名；不在列表中的结果不会落为分类。
2. **AI 凭据**：Provider、模型、密钥和可选 base URL。当前支持 OpenAI、Qwen、GLM、Kimi、Claude、Gemini。
3. **AI 策略**：一段由用户填写的规则文本，绑定一份 AI 凭据。非空、非注释行会拼入提示词。
4. **Pipeline 步骤**：目前只有 `ai_classify` 类型。每条步骤选择一份 AI 策略，可设置“仅未分类”、并发上限、启用状态和顺序。

数据库中的 `ai_strategies.active` 字段目前不参与分类判断，页面不再提供这个无效开关。实际是否运行由 Pipeline 步骤的 `enabled` 决定；若用户未配置启用步骤，上传后账单保持未分类。关键词字典目前只支持维护，没有内置策略读取它。

## 何时执行

- **上传时自动执行**：用户选择支付宝或微信 CSV/XLSX 后，系统建立上传任务，在同一后端进程的后台任务中解析、插入新账单并提交，再对这些新账单运行 Pipeline，最后回写分类。无需另点“开始分类”。重复账单会跳过，也不会因为重复上传而重新分类。
- **单笔手动重分类**：明细页“重分类”会调用 `POST /bills/{id}/reclassify`，同步重跑这笔账单。尚无“重跑所有账单”的页面或接口。
- **凭据测试**：AI 凭据页的“测试”只测试给定样例，不修改账单。

## 顺序和覆盖

系统仅加载当前用户启用的步骤，按 `sort_order`、步骤 ID 升序运行。默认 `only_unclassified=true`，所以先命中的类别成为终态，后面的同类步骤不会再处理它。将某步骤的 `only_unclassified` 设为 `false` 时，它可以处理并覆盖先前**自动**分类的结果。人工分类的账单始终跳过 AI。

每笔账单保存命中的 Pipeline 步骤 ID、策略类型，以及 AI Provider 和置信度。单笔 AI 调用失败通常记录日志并跳过该笔；步骤级异常也会记录日志，后续步骤继续执行。上传任务状态表示解析及批处理完成，不等于每笔都成功分类；可查看 `classified_rows`。

## 最终修改

明细页可手工更改类别。更改后 `manual_overridden=true`，以后 AI 不覆盖。账单标签可独立逐笔编辑；编辑标签不改变类别和人工分类标记。明细页可按月份、平台来源、类别、标签和关键词过滤账单。

## 尚未实现

精确匹配、正则、跳过、合并、退款扩散等“高级策略”只列为未来候选。新增策略类型时还需检查前端参数表单对新字段类型的支持情况。
